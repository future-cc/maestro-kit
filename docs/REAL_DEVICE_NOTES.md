# 真机（小米 / HyperOS）实测记录

日期：2026-10-25。设备：Redmi 24117RN76G（Android 15，HyperOS 2.0），USB 连接，一台。Maestro 2.11.0。
范围很小：一个真实业务 Flutter 应用的**单次**登录冒烟，加上对 Maestro 在这台手机上能否工作的排查。**没有做重复运行，不能据此说明稳定性。**

## 要先在手机上做的设置（否则 Maestro 装不上驱动）
开发者选项里打开：**USB 调试**、**USB 调试（安全设置）**（可能要先登录小米账号）、**USB 安装**。

## 发现

| # | 现象 | 影响 | 应对 |
|---|---|---|---|
| R1 | **每次运行，Maestro 往手机装自己的驱动时，系统都弹“安装”确认；没人点就报 `INSTALL_FAILED_USER_RESTRICTED: Install canceled by user`。** 驱动在每次运行结束后会被卸掉，下次又要装。用 adb 装普通 APK 也一样要点确认 | 默认情况下这台手机只能**有人守着**跑；`--repeat 20`、无人值守回归都做不到（每一次运行都要点一次） | **已验证的解法：给 Maestro 加 `--no-reinstall-driver`**（`e2e.sh` 会原样透传；`Maestro` 帮助里写明“Android 上跳过驱动和服务端 App 的重装”）。第一次运行装上驱动并点一次确认，之后驱动留在手机上：之后连续跑了 2 次 + 5 次（含 `e2e.sh --repeat 5`）都没有再弹确认，驱动包一直在。**代价**：驱动一直留在手机上；Maestro 升级后驱动版本变了需要去掉该参数跑一次让它重装（这一点**未验证**）。用法：`bash .maestro/kit/e2e.sh <flow> --repeat 20 --no-reinstall-driver` |
| R2 | **Maestro 的 `launchApp` 报 COMPLETED，但 App 没有到前台**，手机停在桌面（或上一个页面），后面的等待超时。用 `adb shell am start -n <包>/<Activity>` 直接启动同一个 App 是好的（已复现两次）。原因未查清（可能是 HyperOS 对后台拉起界面的限制） | 用例的第一步就失败，归类为“断言不成立”，很容易误判成 App 问题 | **已加配置项 `PRE_FLOW_CMD`**（`e2e.config` 里，每个 flow 运行前执行，`--repeat` 的每一次也会执行），用 adb 先冷启动 App，用例里不再用 `launchApp`。例：`PRE_FLOW_CMD="adb shell am force-stop <包名>; adb shell am start -n <包名>/<Activity>; sleep 6"`。在这台手机上用它 + `--no-reinstall-driver` 连续跑了 5 次“App 在前台且显示首页”的只读检查，5/5 通过，最后一张截图确认是 App 首页 |
| R3 | **被测应用的当前构建里，登录页控件没有 `resource-id`**（旧用例用的 id 选择器全找不到，`uiautomator dump` 里只有无障碍描述，如“登录”按钮的描述文字）。App 本身能正常用 | 依赖 id 的用例在这个构建上全部失败 | 临时改用文字（“登录”）和百分比位置；根治是按 DEV_CONVENTIONS 给控件加固定标识，并保证测试包里带着它 |
| R4 | 首次进入一个“已登录”的应用，用例的“先退出再登录”流程可以走通；登录后首页的**加载骨架屏**出现在“点击登录”之后的截图里，正向等待（等首页的固定元素出现）之后才是真正的首页 | 只拍一张“点击后”的截图会拍到骨架屏 | 用正向等待再截图；本次用例已是这样 |

## 单次冒烟的结果
登录用例 **1/1 通过**（19 步，43 秒）：输入账号和密码、点登录、等到首页固定元素出现、确认首页没有“登录”入口。已打开“点击登录后”和“登录后首页”两张截图确认：前者是加载中，后者是正常首页，**没有验证码或手机号校验**。（这台手机此前已由人在场登录过，对该账号很可能已是“已授信设备”；这一点**没有核实**。）

## 现在怎么在这类手机上做稳定性测试
1. 手机上打开上面三项开发者设置；
2. 在 `e2e.config` 里写 `PRE_FLOW_CMD`（见 R2）；
3. 第一次运行时守着手机点一次“安装”，然后 `e2e.sh <flow> --repeat 20 --no-reinstall-driver`，之后可无人值守；
4. 用例里不要用 `launchApp`，开头用正向等待首屏元素。

注意：这只验证了“空检查”流程能连续无人值守地跑，**还没有用真实业务用例做过 20 次**。应用自己的随机弹窗（实测出现过应用内的消息弹窗盖在列表上）会让用例偶发失败，这正是要跑 20 次的原因。

## 没有验证的
- 真实业务用例在这台手机上连续多次运行的稳定性（只验证了空检查 5 次；登录用例只跑了 1 次，且在正式环境上反复登录有触发风控的风险）。
- 待办 / 笔记两个离线应用在这台手机上的表现（安装确认没人点，没有装上）。
- R2 的真正原因；Maestro 升级后驱动版本不一致时 `--no-reinstall-driver` 的行为；`PRE_FLOW_CMD` 没有加进 `selftest/`（需要设备上有可启动的 App，自测没覆盖）。
- 别的品牌 / 别的系统版本的真机。
