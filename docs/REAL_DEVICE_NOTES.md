# 真机（小米 / HyperOS）实测记录

日期：2026-10-25。设备：Redmi 24117RN76G（Android 15，HyperOS 2.0），USB 连接，一台。Maestro 2.11.0。
范围很小：一个真实业务 Flutter 应用的**单次**登录冒烟，加上对 Maestro 在这台手机上能否工作的排查。**没有做重复运行，不能据此说明稳定性。**

## 要先在手机上做的设置（否则 Maestro 装不上驱动）
开发者选项里打开：**USB 调试**、**USB 调试（安全设置）**（可能要先登录小米账号）、**USB 安装**。

## 发现

| # | 现象 | 影响 | 应对 |
|---|---|---|---|
| R1 | **每次运行，Maestro 往手机装自己的驱动时，系统都弹“安装”确认；没人点就报 `INSTALL_FAILED_USER_RESTRICTED: Install canceled by user`。** 驱动在每次运行结束后会被卸掉，下次又要装。用 adb 装普通 APK 也一样要点确认 | 这台手机只能**有人守着**跑；`--repeat 20`、夜间无人值守回归都做不到（每一次运行都要点一次） | 稳定性测试放在模拟器上做；真机只做有人在场的单次冒烟。未验证：「USB 安装管理」里有没有“始终允许”之类能免确认的选项 |
| R2 | **Maestro 的 `launchApp` 报 COMPLETED，但 App 没有到前台**，手机停在桌面（或上一个页面），后面的等待超时。用 `adb shell am start -n <包>/<Activity>` 直接启动同一个 App 是好的（已复现两次）。原因未查清（可能是 HyperOS 对后台拉起界面的限制） | 用例的第一步就失败，归类为“断言不成立”，很容易误判成 App 问题 | 这台手机上由外部脚本先用 adb 冷启动 App，用例里不再用 `launchApp`（只对这类手机，模拟器不需要） |
| R3 | **被测应用的当前构建里，登录页控件没有 `resource-id`**（旧用例用的 id 选择器全找不到，`uiautomator dump` 里只有无障碍描述，如“登录”按钮的描述文字）。App 本身能正常用 | 依赖 id 的用例在这个构建上全部失败 | 临时改用文字（“登录”）和百分比位置；根治是按 DEV_CONVENTIONS 给控件加固定标识，并保证测试包里带着它 |
| R4 | 首次进入一个“已登录”的应用，用例的“先退出再登录”流程可以走通；登录后首页的**加载骨架屏**出现在“点击登录”之后的截图里，正向等待（等首页的固定元素出现）之后才是真正的首页 | 只拍一张“点击后”的截图会拍到骨架屏 | 用正向等待再截图；本次用例已是这样 |

## 单次冒烟的结果
登录用例 **1/1 通过**（19 步，43 秒）：输入账号和密码、点登录、等到首页固定元素出现、确认首页没有“登录”入口。已打开“点击登录后”和“登录后首页”两张截图确认：前者是加载中，后者是正常首页，**没有验证码或手机号校验**。（这台手机此前已由人在场登录过，对该账号很可能已是“已授信设备”；这一点**没有核实**。）

## 没有验证的
- 在这台手机上连续多次运行的稳定性（R1 使它无法无人值守）。
- 待办 / 笔记两个离线应用在这台手机上的表现（安装确认没人点，没有装上）。
- 「USB 安装管理」能否免确认；R2 的真正原因。
- 别的品牌 / 别的系统版本的真机。
